# 十台底盘电机首版逐台测试

本版目标是逐台验证反馈、转向和闭环。默认不选电机、不运行。调试器提供目标，遥控器沿用原板间链路和 SW2 总许可；不新增控制任务。

## 接线和电机配置

| 调试编号 motor | 电机 | 总线 | 硬件电机 ID | 反馈 CAN ID |
|---|---|---|---|---|
| 1 | 右前麦轮 M3508 | CAN1 | 1 | 0x201 |
| 2 | 左前麦轮 M3508 | CAN1 | 2 | 0x202 |
| 3 | 左后麦轮 M3508 | CAN1 | 3 | 0x203 |
| 4 | 右后麦轮 M3508 | CAN1 | 4 | 0x204 |
| 5 | 左履带 M3508 | CAN3 | 1 | 0x201 |
| 6 | 右履带 M3508 | CAN3 | 2 | 0x202 |
| 7 | 右前腿 J4340 | CAN2 | 1 | 0x11 |
| 8 | 左前腿 J4340 | CAN2 | 2 | 0x12 |
| 9 | 左后腿 J4340 | CAN2 | 3 | 0x13 |
| 10 | 右后腿 J4340 | CAN2 | 4 | 0x14 |

CAN1、CAN3 分别发送自己的 `0x200` C620 四槽电流帧，CAN3 后两槽恒为零。两路相同反馈 ID 分别分发，互不混用。

J4340 必须预先配置 MIT 模式、电机 ID 和反馈 ID。现有驱动采用 `PMAX=12.5 rad`、`VMAX=10 rad/s`、`TMAX=28 N·m` 的协议编码范围，须与电机实际配置一致。这里的范围是协议换算参数，不是机械行程或持续负载能力。程序不修改电机模式、ID、内部零点或 Flash；沿用用户已完成的零位标定。

硬件时钟与三路 CAN 时序保持原工程配置，实际电调配置及接线仍需上板核对。

## 调试器输入和观测

将 `g_chassis` 加入 Keil Watch，编辑 `command`，其余状态用于读取。

| 字段 | 含义 |
|---|---|
| command.motor | 上表中的 1～10；0：不选电机 |
| command.run | 0：停止；1：请求运行，同时还必须取得遥控许可 |
| command.speed_rpm | 3508 减速前电机转速，带正负号，单位 rpm |
| command.position_deg | J4340 输出轴绝对角度，单位度 |
| command.leg_kp | H7 位置增益，N·m/rad；默认 5.0 |
| command.leg_kd | H7 阻尼增益，N·m·s/rad；默认 0.2 |
| active_test_motor | 实际正在处理的编号；旧腿停止确认期间仍显示旧编号 |
| test_status | 下表中的当前状态/错误 |
| wheel_motor / track_motor | DJI 电机速度、电流和最近反馈时间 |
| leg_motor | J4340 实际位置 rad、速度 rad/s、状态码和反馈序号 |
| leg_submitted_torque_nm | 最近成功提交的 MIT 力矩，含协议限幅、编码前值；不是实测力矩 |

腿增益初值只是首轮悬空调试的起点，未验证承载效果。调试器没有多字段事务保护：先 `run=0`，完成电机选择后让任务运行至少一周期，再设置 `run=1`；不要在 CPU 暂停时一次写完选择、目标和 run 后期待直接执行。

| test_status | 数值 | 含义 |
|---|---|---|
| CHASSIS_TEST_IDLE | 0 | 停止/未运行 |
| CHASSIS_TEST_REMOTE_LOCKED | 1 | 遥控输出许可关闭，测试 run 已清除 |
| CHASSIS_TEST_WAIT_FEEDBACK | 2 | 等待被选中电机的首个新鲜反馈 |
| CHASSIS_TEST_ENABLING | 3 | 零力矩预置并发送使能，等待新使能反馈 |
| CHASSIS_TEST_RUNNING | 4 | 正在执行所选闭环 |
| CHASSIS_TEST_STOPPING | 5 | 已发停机请求，等待旧腿的新失能反馈 |
| CHASSIS_TEST_INVALID_COMMAND | 6 | 编号、run、目标或增益无效 |
| CHASSIS_TEST_FEEDBACK_LOST | 7 | 运行中的被测电机反馈超时 |
| CHASSIS_TEST_MOTOR_FAULT | 8 | J4340 报故障、运行时失能或反馈数值异常 |
| CHASSIS_TEST_SEND_FAILED | 9 | CAN 帧入队失败 |

## 3508 逐台测试

1. 首测使轮/履带悬空。保持 `command.run=0`，选择 `command.motor=1～6` 中的一台。
2. 让任务运行一周期。选择变化会自动清 run，并把 `command.speed_rpm` 清为零；然后再设置测试转速，例如 `100` rpm。
3. 通过原板间遥控链路取得许可。仍是原 SW2 上拨边沿解锁、下拨边沿锁定；上电已有上拨状态不等于出现了解锁边沿。
4. 设置 `command.run=1`。确认 `test_status=RUNNING`，读取对应电机反馈；只给这一台反馈即可，不要求其他九台在线。
5. 修改正负转速检查方向。速度环沿用原 `Kp=10、Ki=0、Kd=0` 和 C620 电流编码边界，不另加测试转速限幅。
6. 设置 `run=0` 停止，再选择下一台。未选中 3508 的输出是零电流，不是零速刹车；轮子可能继续惯性转动。

## J4340 逐台测试

1. 保持 `run=0`，选择 `motor=7～10` 中的一台，等待选择被处理。测试前自行确认实际运动空间。
2. 取得原遥控输出许可后设置 `run=1`。任务先等待本电机反馈，再成功发送零力矩预置和 MIT 使能请求。
3. 等待 `test_status=RUNNING`。只有使能请求之后的新反馈确认了使能，才把 `command.position_deg` 初始化为当前绝对角度；使能前填入的旧目标会被覆盖。
4. 此时再修改 `command.position_deg`。H7 按下式计算，角度在内部换算为 rad：

   `tau = leg_kp * (position_deg * pi / 180 - feedback_position_rad) - leg_kd * feedback_velocity_rad_s`

   MIT 报文中的位置、速度、kp、kd 均为零，只通过力矩字段执行 H7 PD 输出。目标角度不回绕、不限制机械行程、不使用 ±3° 测试窗口；输出只沿用现有驱动的协议编码范围。

5. 设置 `run=0` 或锁定遥控。任务发送零力矩和失能请求；失能后腿不保持位置，支撑方式须由实际测试条件保证。
6. 等待 `active_test_motor=0`，再选择下一台。旧腿未返回本次失能请求之后的新失能反馈时，保持停止确认，不启动新电机；缺失其他未选中腿的反馈不阻止测试。

腿管理请求每 20 ms 发送一次，控制沿用原 1 ms 任务通知节拍；不在任务内阻塞等待 CAN 或电机响应。

## 停止、切换与错误恢复

更改电机编号会清 run、复位速度 PID 并停止旧电机。遥控关闭许可、被测反馈超过 50 ms、目标数值无效或发送失败，也会清 run；恢复反馈/遥控后需要重新手动设置 run。初始等待反馈期间请求会保留，首个有效反馈到达后可继续进入测试。

未选中的腿周期接收失能命令。零电流、失能或命令入队成功不证明机械已停止；状态确认依赖真实反馈。

当前未接麦轮解算、遥控摇杆速度映射或四轮联动，也不保留模式切换入口。3508 的目标仅来自 `command.speed_rpm`，摇杆移动不会生成任何电机目标；遥控器仍提供总使能许可。

板间遥控是否有效仍沿用原 `remote_valid/rc_lost` 语义，本轮未加入新的板间报文超时判定。当前绿灯只反映原输入许可，不能当作被测电机已运行的证据。

## 已完成的离线验证与边界

从工程根目录运行 `python Chassis/tests/run_motor_tests.py`。测试编译真实控制器、CAN 分发、DJI/DM 驱动与 PID，仅在独立主机测试程序里替换物理 HAL 和时钟，不加入固件。

GCC、Clang 检查涵盖十个编号、三路 CAN 的帧过滤、同 ID 隔离、单反馈运行、正负电流及未用槽清零、PD 单位与 MIT 纯力矩字段、目标初始化、无软件角度限位、使能/失能新反馈确认、切换、反馈超时与计时回绕、异常值、电机故障、发送失败，以及摇杆不会生成麦轮联动目标。

反馈检查的当前时间与快照在同一临界区内读取。回归用例在进入临界区前注入下一毫秒的真实 CAN 解码回调，覆盖六个 3508、四个 J4340 和失能确认，防止将新鲜反馈误判为超时并清 run；50 ms 超时阈值和 uint32 计时回绕语义保持不变。

Keil/AC6 完整构建通过。EIDE 统一构建器也使用当前 `.eide/eide.yml` 的源码/包含目录完成独立构建；验证输出位于 `build/chassis_motor_test/eide`。本机缺少构建器要求的 .NET 6，验证进程单独用 `DOTNET_ROLL_FORWARD=Major` 在已安装的 .NET 8 上运行，未更改系统或编辑器环境。

尚未烧录或取得实机 CAN、实际动作、方向和控制增益数据；离线验证不能替代这些台架验证。CubeMX 生成文件未修改，本轮未重新生成工程。
